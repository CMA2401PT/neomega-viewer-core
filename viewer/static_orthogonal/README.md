# 静态正交渲染

这个包把已确定颜色的方块绘制为静态正交图片瓦片。
相机在一次渲染中保持不变，因此立方体的覆盖范围、面朝向和逐像素相对深度都可以预先计算。
运行时只移动贴图、查询面色并比较深度，不生成场景网格。
尺度为 1 时采用单像素点路径，每个方块只向中心投影所在的一个像素写入原色和深度。

为了按内存配额处理大地图，核心只拥有调用者指定的一块图片。
存档读取、区块缓存、并发调度和 PNG 写出由 [正交全景应用](../../../apps/neomega-large-neomega-viewer-orthogonal/README.md) 负责。

## 投影与遮挡

`Atlas` 是一个固定相机的贴图表。
`NewAtlas` 将屏幕基向量量化到 1/16 像素，并预绘制 16×16 种锚点相位。
相位表示锚点在像素内部的位置。
所有方块共享同一覆盖掩码和相对深度，三种面色则在瓦片内按 RGB 有界缓存。
这样无需为每个方块状态复制整套像素。

`Scale=1` 时跳过形状贴图生成和面明暗计算。
点投影使用 1/65,536 像素的定点基向量，避免低尺度放大量化后的相机角度误差。
最后将方块中心落到一个整数像素，重叠点只保留深度更近的颜色。

`Project` 把方块坐标和颜色变为 `Stamp`，也就是可直接绘制的贴图位置。
`Draw` 将贴图深度加上方块位置的深度，与目标像素比较。
因为每个像素独立比较深度，所以输入顺序不影响遮挡。
共边采样采用一致的归属规则，避免内部方块剔除后留下对角缝。
同深度的重叠颜色按固定次序取值，使乱序输入的结果可复现。

应用需要确定读取范围时，可用 `BoxBounds` 将世界包围盒投影为图片范围。
反过来，`Footprint` 结合图片范围和世界高度上下界，得到可能影响这些像素的水平世界范围。
`Facing` 给出朝向观察者的邻格方向，供应用剔除内部方块。

## 颜色语义

立方体模式中，每个可见方块都是不透明的完整立方体。
应用可复用 `topview` 的 Java 状态颜色表，未知状态自行选择回退色。
点模式同样使用不透明颜色，但不做分面的明暗处理。
水、玻璃、植物和半砖也按颜色立方体处理。
该路径适用于大尺度地图全景，不重现资源包模型形状或透明材质混合。

RGB 使用低 24 位，黑色 `0x000000` 是有效颜色。
空气应由调用者跳过，不能用黑色表示空气。
相机方位 `Yaw=0` 表示从 +Z 看向原点，`Yaw=90` 表示从 +X 观察。
俯角 `Pitch=90` 是正俯视，`Scale` 是每个世界单位的像素数。
接近水平、量化后无法从高度反算水平位置的相机参数会返回错误。

## 最小用法

下面的瓦片使用全局像素坐标，负坐标同样有效。
多个工作协程可以共享一个 `Atlas`，每个工作协程独占自己的 `Tile`。

```go
atlas, err := ortho.NewAtlas(ortho.Camera{
    Yaw: 45,
    Pitch: 35.26438968,
    Scale: 4,
})
if err != nil {
    return err
}
tile := ortho.NewTile(image.Rect(-256, -256, 256, 256), color.NRGBA{})
atlas.Draw(tile, atlas.Project(0, 0, 0, 0x8b9473))
atlas.Draw(tile, atlas.Project(0, 1, 0, 0x507b35))
return png.Encode(output, tile.Image)
```

这里的 `ortho` 是 `neomega-viewer-core/viewer/static_orthogonal` 的导入别名。
例子还需要标准库的 `image`、`image/color` 和 `image/png`。
`output` 是调用方提供的 `io.Writer`。

每个瓦片的主要存储是每像素 4 字节颜色和 8 字节深度。
`Reset` 可将已有瓦片移动到同尺寸的新区域，并清空上一块图片的深度和颜色。
调用方必须保持宽高不变。

## 验证

从工作区根目录运行：

```sh
./check.sh neomega-viewer-core
```

测试覆盖单像素点大小、点遮挡、乱序输入、负坐标、正俯视遮挡、黑色不透明、实心立方体接缝及瓦片拼接一致性。
应用测试另外将跨柱剔除、反投影读取和分带输出，与不剔除任何方块的整图绘制逐像素比较。
