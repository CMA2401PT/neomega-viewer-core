# 多层渲染方案：一格叠放多个模型

含水台阶在 Java 里没有自己的模型，它的画面是「台阶模型 + 水模型」叠在同一格里。单层的 mesher 假设一格 = 一个
hash = 一组模型，画不出这种方块。本文说明怎样让一格容纳多个模型：先把方块拆成多层，再让 mesher 一次渲染多层。

整体分两步，各在不同的地方：

```text
JavaBlockHash ──SplitLayer（mesher 之外）──▶ [][]JavaBlockHashRSL ──MeshLayers──▶ 网格
  含水台阶                                    第 0 层：台阶  第 1 层：水
```

## 两种 hash：JavaBlockHash 与 JavaBlockHashRSL

`waterlogged=true` 的台阶是合法的 Java 方块，理应有自己的 hash；但它对应两个模型，不能直接当几何表的键。
所以要分开两个概念：

- **JavaBlockHash**：任意合法 Java 状态（Tidy 后 Hash）。可能需要多个模型才能画出来。
- **JavaBlockHashRSL**（Render Single Layer）：一个 hash 只对应一层、一组模型，是几何表 `Tables.Index` 的键。

两者用同一种哈希算法，数值空间不必区分，区分靠接口类型。

现有的 hash 事实上已经是 RSL。我们的 Java 状态全集（`neomega-blocks/presets/java/v1` 的
`java_block_schema.list` 与 `fan_out_java_full.list`）里没有任何方块带 `waterlogged` 属性：上游
PyMCTranslate 把水当作每个方块都可以叠加的附加方块，不算进单个方块的属性；建表时
`neomega-viewer-core/viewer-assets/cmd/build-tables/internal/tablegen/tables.go` 再按 `waterlogged=false` 补齐以选模型。改名只是把这个事实说清楚。

## SplitLayer：把一个方块拆成多层

SplitLayer 把一个方块变成一列 RSL，下标即层号。规则本身定义在方块状态上，只看一眼属性：

- 有 `waterlogged` 属性：去掉它放进前景层；值为 `true` 时，再在后景层放一格 `water[level=0]`。
- seagrass、tall_seagrass、kelp、kelp_plant：它们没有 `waterlogged` 属性，却总是长在水里（隐式含水），
  原样放前景层，后景层放水。这是规则里唯一需要按方块名列举的部分。
- 其余方块原样放前景层。

不需要「哪些方块能含水」的名单，`waterlogged` 对任何方块都按同一条规则处理。

| 输入（完整 Java 状态） | 输出 |
|---|---|
| 石头 | `[石头]` |
| 台阶，waterlogged=false | `[去掉 waterlogged 的台阶]` |
| 台阶，waterlogged=true | `[去掉 waterlogged 的台阶, water[level=0]]` |
| kelp | `[kelp, water[level=0]]` |

`presets/java/v1` 的 `HashToBlock` 可以反查原状态及 `waterlogged=true/false` 两种变体，状态全集迭代器仍只枚举原状态。
SplitLayer 把拆层规则预先展开成 `JavaBlockHash → []RSL` 表，让运行时直接按 hash 取得拆层结果。初始化时遍历全集，
每个状态分别以「原样」「补 `waterlogged=true`」「补 `waterlogged=false`」三种形式套用规则。多个 Splitter 共享这张只读表。

几点说明：

- **不拆层也可能要换 hash。** `waterlogged=false` 和去掉这一位的状态文本不同、hash 不同。
- **hash 相同也可能要拆层。** kelp 的 JavaBlockHash 就是它植物层的 RSL，但仍要补一层水。
- **SplitLayer 不能重复调用。** 把 kelp 的 RSL 当输入再拆一次，会多出一层水。
- **它只拆、不补。** 输入若已经是丢了 `waterlogged` 的旧 hash，就无从知道原本是否含水。
- 表里查不到的 hash 原样当作 RSL 返回，交给 mesher 按几何表的结果处理。

层的组织：每格层数可变，规则目前最多产生两层，接口不固定为两层。一个子区块的层数取各格的最大值，某格在某层
没有方块就填 air 的 RSL。层号只表示同一格内的先后，不表示介质：一格普通水在第 0 层，含水台阶的水在第 1 层。

SplitLayer 放在 viewer 的独立包 `splitlayer`，是送进 mesher 之前的输入准备。RSL 的定义就是
blocks 几何 preset 的键（去掉 `waterlogged` 的状态），所以拆成什么样由 viewer 决定。规则以方块状态为输入，hash 表
只是它的展开。调用方手里是 blockstate 时，可以直接调用 `SplitBlock`。

演示服务的子区块输入是 JavaBlockHash。启用 `fix=1` 时，两条入口的修复顺序不同：

- `GET /api/subchunks/{scene}/frame` 与 `POST /api/subchunk/frame` 先由 neomega-converter 的 fixer 修复完整 hash 层，再交给 Pipeline 拆层、分发并渲染。
- `GET /api/subchunks/{scene}/mesh` 与 `POST /api/subchunk` 先拆层，只修复第 0 层，再交给 `MeshLayers`。

## MeshLayers：一次渲染多层

接口：`MeshLayers(layerBlocks [][]B, options)`，第一维是层，第二维是构建器约定的 N³ 格。
`MeshLayer(blocks)` 变成只有一层的特例，内部走同一条路径，避免两套逻辑分叉。

### 不逐层调用 MeshLayer，而是按位置合并

最省事的做法是每层调一次 `MeshLayer` 再拼接结果。它的问题是层与层之间互相看不见：后景层的水挨着前景层的
石头，水的侧面不会被剔掉；同格台阶和水的共面面也会叠在一起闪烁（z-fighting）。贪心合并不会替你消掉这些面。

所以按位置合并：每格把各层的 Shape 收进同一个 `meshing.Cell`，再做一次剔面和合并。邻格剔面已经天然支持，
`meshing.subtractNeighbor` 本来就遍历邻格的所有 Shape、按各自的材质和 CullGroup 判定，邻格来自哪一层无关紧要。

但 Cell 里要记下每个 Shape 是哪一层的。层号属于这次摆放，不能写进共享的 Shape；同一 RSL 的 multipart 部件
属于同一层，部件顺序不是层序。

流程：

```text
各层 RSL 查几何
  → 收集每格的流体
  → 根据上方格选每个流体的高度
  → 同格共面裁切 + 邻格边界裁切（对每个原始面一并处理）
  → 一次贪心合并
```

### 「前层叠在后层上」的含义

这句话不能理解成「第 0 层在画面上永远盖住第 1 层」。三维渲染靠深度缓冲决定遮挡：水面虽在后景层，只要它在
相机和水草之间，就该挡住、混合水草的颜色。输出也会按材质分批、透明面另行排序，输入顺序并不决定绘制顺序。

层序用于同格共面覆盖和后层缩进。同一格内两个面共面时，前层的完全不透明面可以裁掉后层同平面、同朝向的重叠部分。
透明或镂空的前层保留后层，植物贴图的透明处才能透出水。前方存在满立方体层时，后层按与最近一个满立方体层的层号差缩进，
规则见下文。

### 同格共面裁切

只把 Shape 并进同一格，会让含水下半台阶保留两套面：台阶底面和水底面都在 `y=0`，侧面下半截也共面。这正是
需要同格裁切的地方。Java 自己的流体渲染也会按所在格方块的遮挡形状剔掉水面（`LiquidBlockRenderer` 里的
`isFaceOccludedBySelf`，凭记忆未联网核实）。

它和邻格剔面是两种关系，不能直接复用 `occludes`：

- 邻格比较相对的两个边界面；同格比较同平面、同朝向的面。
- 是否裁切不看 `CullFace`。这个字段表达「模型允许哪个方向的邻居剔掉它」，不是层间覆盖许可。
- 邻格同组水面是内部界面，两边都消掉没问题；同格两个重合的水面若互相消掉，会把该留的外表面一起删了。

矩形识别和减法复用 `neomega-viewer-core/viewer/geometry` 的 `InspectRectangle` 与 `Subtract`，先只处理轴对齐矩形。

### 满立方体前景：后层缩进

共面裁切只认不透明的前层。含水树叶的前景是镂空材质，裁不掉后层，树叶侧面和水的侧面共面，画面会闪
（z-fighting）。

办法是缩进：某格里若有更靠前的层是完整的单位立方体（六个方向的边界都盖满整面，只看形状不看材质，树叶、玻璃都算），
这一格后面的层以格子中心为基准缩小，系数为 0.99^(与最近一个前方满立方体层的层号差)。被缩进的面保留全部面片。
相邻两层的单侧缩进为 0.005 格，可以分开共面表面。保留这些面片的代价是少剔掉一些内部面。
邻格查询仍使用各层未缩进的原始 `Boundary`，即 Shape 保存的格子边界覆盖。旁边普通水朝向含水树叶的面，由树叶格内
同消面组的后层水提供覆盖并剔除。

系数实测过三档：0.99 不闪；0.995 和 0.999 在镜头拉远时会闪，缩进太小，深度缓冲的精度分不开两个面。

实体内部的面不处理。上半台阶占 `y=0.5…1`，源水顶面在 `y=8/9`，正好藏在台阶里；现有的 `Boundary` 只描述
格子边界，表达不了这种内部遮挡。但台阶是封闭不透明的，从外面看，这块水面会被深度缓冲挡住，画面是对的，代价
只是多留几个看不见的面。等哪天要求网格严格不含实体内部的流体，再考虑体积信息。

### 流体满高度跨层判断

上方格任意层有同组流体时，本格对应的流体 Shape 就换成满高度几何。例如本格普通水在第 0 层、上方含水台阶的水在
第 1 层，也是连续水体。

`prepareNeighborhood` 先收集所有层的原始几何，再逐个流体 Shape 选择高度，因此结果不受遍历顺序影响。
替换只作用于对应的流体引用，同格的台阶和植物保持原样。

跨区域构建时，`MeshWithNeighbours` 用相对中心的区域坐标查询邻居。水平邻居的顶层同样需要其上方区域，才能为连续水体提供完整的侧面覆盖；若缺少这份数据，区块交界处会残留一条竖直水面。`NeighbourOffsets()` 返回所需区域的位置，`Pipeline.BuildSections` 会自动读取并缓存它们。

### Stats 口径

延续单层的含义，按位置而不是按层计：

| 字段 | 多层下的含义 |
|---|---|
| `Blocks` | 裁切前有几何的位置数；台阶加水算一个位置 |
| `Shapes` | 实际用到的不同共享 Shape 数 |
| `InputQuads` | 选完流体高度、任何裁切之前的面数 |
| `RemovedQuads` | 经同格与邻格裁切后完全消失的原始面数 |
| `ClippedQuads` | 只剩一部分的原始面数 |
| `VisibleQuads` / `OutputQuads` | 贪心合并前 / 后的面数 |

一个面先被同格裁掉一部分、再被邻格整个剔掉，只计入 `RemovedQuads`。`DisableCulling` 同时关闭两种裁切。

## 用场景检验闪烁

`waterlogged` 场景用于检查同格裁切、后层缩进和跨层流体连接的效果：

- 含水下半台阶、楼梯：共面的底面和侧面应被裁掉。
- 含水上半台阶：水面藏在台阶内部。
- 含水栅栏：检查非满格前景与水的交界。
- 含水树叶：水层缩进后，共面表面应保持稳定。
- 海草、海带：隐式含水。
- 水池中夹一格含水台阶：跨层的同组水面要互相剔掉。
- 含水台阶上方叠水：下层的水要跨层判断成满高度。
