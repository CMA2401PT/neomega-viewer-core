# 分层颜色体素

这个包用规则网格中的颜色编号表示完整立方体，由 WebGL 2 对每个屏幕像素查找首个可见方块。
Go 负责准备和序列化数据，浏览器负责正交相机、遍历和绘制；包内不读取存档。

为了避免整张世界展开成顶点，空间分为 8×8×8 的小块。
同色小块只保存一个编号，混合小块保留每格一个字节。
上层目录逐级合并同色区域，射线可以整段跳过空气，并直接命中同色实心区域。
混合小块内部使用逐网格边界的 DDA 遍历；跨界轴由整数坐标决定，避免浮点误差使射线停在原格。

## 准备数据

生成场景可以调用 `Build`，按坐标回调提供小块。
逐区块读取的来源可以用 `NewBuilder` 创建目录，调用 `AddBrick` 提交小块，最后调用 `Finish` 构建层次。
每个位置只提交一次。起点按 8 格对齐，每轴尺寸为不小于 8 的二次幂，范围内未提交的位置为空气。

调色板条目为 RGBA，编号 0 表示空气，1…255 表示不透明方块。
黑色可以使用非零编号，不会被当作空气。
小块数组按 `x + 8*(y + 8*z)` 排列，提交时复制，因此来源可以复用缓冲。

## 数据与绘制

`Volume.Write` 写出小端序的 JSON 头长度、补齐到四字节边界的 JSON、调色板、由细到粗的目录与混合小块数据。
格式名为 `full-view-1`，JSON 包含世界起点、尺寸、各层目录尺寸与小块数据长度。
应用可以对整个输出压缩，不改变核心格式。

`web/volume.ts` 解码连续数据，数组借用输入缓冲。
`web/renderer.ts` 一次上传纹理，随后每帧只更新相机参数。
目录使用整数三维纹理，混合小块放入分层二维纹理，调色板单独查色。
纹理数据预算为 2 GiB，实际可用尺寸还受设备的纹理边长和层数限制。

相机支持上下观察、平移和缩放。每个像素采用一条射线，没有远景几何简化或抗锯齿，因此远处细碎结构可能出现采样闪烁。
遍历次数超出上限时输出紫色，暴露未完成的射线。

完整应用与离线导出命令见 [neomega-full-view](../../../apps/neomega-full-view/README.md)。
