# 按 NBT 生成完整外观

block actor 把一个方块的完整 Java 状态和实体 NBT，转换为可直接绘制的网格与可选的私有贴图。
陶罐从自身携带的图片中选择四面纹样，旗帜则在 Go 合成自己的旗面图片。告示牌在 Go 排版双面文字，也随网格交付所需像素。
分发器和浏览器只认识这份产物，不解释陶片、图案、染料或文字。

## 为什么分开处理器与组装

每种方块的规则放在独立子包，例如 `decoratedpot` 和 `banner`。
`Handler` 是处理器契约：声明支持的方块名，并由 `Build` 返回 `Appearance`，即网格与图片组成的完整外观。
`blockactor.Dispatcher` 根据已注册名称调用它，复制网格并加上格子坐标。
上层的 `dispatcher.Pipeline` 决定静态本体与水层怎样组合，成功时替换本体，失败时保留静态几何并报告 `ActorError`。

哪些处理器应该启用，由 [javapreset](../javapreset/pipeline.go) 组装。
它只选择和注册处理器，并传入几何表。
处理器的 PNG 保存在各自包内的 `textures/`，通过 Go embed 随程序交付，由构造函数一次性解码。
这些图片作为源码资源维护，不依赖图集坐标或资源生成命令。
添加处理器只需修改这个组合，不需要修改两个通用分发器、快照编码器或浏览器中的方块类型分支。
调用者也可以用 `blockactor.New(handlers...)` 与 `dispatcher.NewPipeline(...)` 自行选择组合。

## 几何与图片的约定

处理器返回按状态旋转的格内几何，不能自行加上 `Input.Pos`，因为分发器会统一平移一次。
几何可以超出单位格子；旗帜比一格高，相机与裁剪按实际几何范围工作。
处理器可以复用只读模型；分发器复制四边形后再平移。
图片及输入 NBT 在使用期间保持只读，调用者不能在构建时修改共享资源。

`Texture` 保存处理器生成的图片，像素是从左上角逐行排列的非预乘 RGBA8，RGB 使用 sRGB 编码。
`Pixels` 长度为 `Width × Height × 4`，无需行填充。
材质的 `Surface.Texture` 与图片的 `Name` 相同，就采样当前 actor 的这张图片；`Surface.Region` 相对此图片归一化。
没有同名私有图片时，材质照常采样调用方提供的公共图集。
`Surface` 仍然是可比较的材质键，图片字节不进入这个键。

私有名称只在一个 actor 内有效。
两面旗帜可以都叫 `banner:face`，但有不同的像素，不需要全局名称、内容哈希或服务器图片缓存。
图片随 [NVFR 快照](../merger/FORMAT.md) 到达前端，解码同步创建字节视图。
绘制对象复制图片字节并创建 GPU 贴图，`dispose()` 同时释放自己的图片、材质与几何。
公共图集仍由宿主管理。

世界渲染中，没有私有图片的 actor 继续参与图集合批。
带私有图片的 actor 保留独立绘制对象，随所属区域一起裁剪和卸载；不同图片不会被合到同一次材质采样中。

## 如何增加下一种 NBT 方块

把方块专属的输入解释、外观生成和固定资源放进同一个子包。
告示牌处理器就是这样的实例：它解析文字，在 Go 光栅化文字图片，然后返回牌体网格、文字面和该图片。
只要结果仍是网格与 RGBA 图片，就能复用既有协议和前端，无需让浏览器读取告示牌 NBT。
文字布局与字体加载仍属于告示牌处理器的职责，这里不预先引入通用绘图命令语言。

旗帜的完整实例及支持范围见 [banner/NBT.md](banner/NBT.md)，陶罐见 [decoratedpot/NBT.md](decoratedpot/NBT.md)，告示牌见 [sign/NBT.md](sign/NBT.md)。
