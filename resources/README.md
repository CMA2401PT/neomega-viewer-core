# 手工维护的资源与规则

客户端 JAR 提供了普通方块模型，却无法告诉外部工具如何绘制箱子、旗帜等由游戏代码生成外形的方块。这里集中保存补足这些信息的资源和规则：上游模型与纹理，以及本工具维护的分类和适配代码。它们是构建的输入，中间生成文件放在 `dist/works`，交付文件放在 `dist/final`。

`s04_special` 读取这些输入，导入所需模型和纹理，并检查最终引用。只有 `minecraft:air` 的无几何处理直接留在步骤代码中。把其他具体方块知识放在这里，可以在更新游戏资源时集中检查，通用导入流程继续复用。

## 修改渲染规则

需要增加特殊方块、修正纹理路径或说明新的运行时需求时，修改 [special.go](special.go)。这个文件集中保存不可见、流体和动态方块分类、特殊方块与告示牌的运行时需求、纹理族选择、导入命名规则，以及染色潜影盒的皮肤适配。

规则只描述应该选择什么资源、如何替换模型内容。模型依赖遍历、文件读写和输出检查由第四步负责。新增方块时，先判断现有 JAR 模型是否足够；缺少几何时，再补充相应分类或预览模板。

## 修改附带模板

需要补充静态几何时，使用 [third_party/mc-assets](third_party/mc-assets/README.md) 中的模板。该目录整体保留上游许可证、来源索引、模型和纹理。`go:embed` 把文件编入工具，因此移动目录或部署可执行文件后，运行时仍能读取它们。

更新模板时，从明确的上游提交收录文件及依赖，同步更新索引、作者署名与来源说明。然后运行根 README 的完整构建与 `audit` 命令，检查资源引用、几何覆盖和纹理收录。输入资料的来源与许可见 [NOTICE.md](../NOTICE.md)。

## 查看资源覆盖

需要确认版本更新是否遗漏纹理或特殊方块时，运行根 README 中的 `audit` 命令。[audits](audits/README.md) 保存核对报告和复现命令，报告本身由工具生成。
